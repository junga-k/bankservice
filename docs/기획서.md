# 매치뱅크 (MatchBank)
### AI 뱅킹 에이전트 데모

작성자: junga-k
작성일: 2026-07-23

> 여러 은행을 오가며 상품을 비교하고, 안내만 해주는 챗봇에 답답함을 느낀 적 있다면 — 매치뱅크는 실제로 계좌를 조회하고, 상품을 비교하고, 이체까지 대신 처리해주는 AI 은행원입니다.

---

## 1. 프로젝트 개요 (한눈에)

매치뱅크는 은행 웹사이트에 "AI 은행원"을 심어, 사용자가 대화만으로 실제 은행 업무를 처리할 수 있게 만든 데모 서비스입니다. 단순히 질문에 답하는 챗봇이 아니라, 계좌 조회·상품 비교·이체 신청 같은 업무를 AI가 직접 수행하고, 그 결과를 사용자가 확인·승인하는 구조로 설계했습니다.

**핵심 하이라이트**
- 실제 업무를 수행하는 AI 에이전트 — 안내만 하는 게 아니라 계좌조회·이체·상품추천을 직접 실행
- 금융감독원(FSS) 공식 API로 실시간 상품 (5개) 비교 (예금·적금·주택담보대출·전세자금대출·신용대출)
- 이체는 AI가 "제안"만 하고, 최종 실행은 반드시 사용자 승인 — 안전장치 내장
- 운영자가 AI를 직접 튜닝·모니터링할 수 있는 관리자 도구(백오피스) 포함

---

## 2. 문제 정의 — 왜 만들었는가

시중의 은행 챗봇 대부분은 "자주 묻는 질문에 답하는 봇"에 머물러 있습니다. 계좌를 보려면, 상품을 비교하려면, 이체를 하려면 결국 사람이 직접 메뉴를 눌러가며 처리해야 합니다. 챗봇은 안내판일 뿐, 일을 대신해주지는 않습니다.

또한 대출·예금 상품을 비교하려면 은행마다 앱을 켜고 금리를 하나하나 확인해야 하는 번거로움이 있습니다. 특히 전세자금대출이나 신용대출처럼 은행별 금리 차이가 크고 조건이 복잡한 상품일수록 이 번거로움은 더 커집니다.

한 가지 문제가 더 있습니다. 대부분의 "AI 챗봇 데모"는 만들고 나면 운영할 방법이 없습니다. 답변이 이상해도 무엇이 문제인지 확인할 방법이 없고, 프롬프트나 모델을 바꿔보고 싶어도 코드를 다시 배포해야 합니다.

매치뱅크는 이 세 가지 문제를 함께 풀기 위해 시작했습니다. 그래서 이름도 "AI 챗봇"이 아니라 **"AI 은행원"**입니다. 이 AI는 질문을 받으면 스스로 판단해서 필요한 도구(계좌 조회, 상품 검색, 이체 등)를 호출하고, 그 결과를 다시 확인한 뒤 다음 행동을 정하는 방식으로 동작합니다(기술적으로는 LangGraph라는 프레임워크의 "ReAct 에이전트" 구조를 사용합니다). 즉, "질문 하나에 대답 하나"로 끝나는 일반 챗봇과 달리, 목표를 달성할 때까지 스스로 여러 단계를 거쳐 일을 처리하는 것이 핵심 차이입니다.

## 3. 타겟 정의

문제 정의에서 바로 이어지는, 매치뱅크가 실제로 필요한 사람들입니다.

- **① 금융 상품을 비교해야 하는 소비자** — 여러 은행 앱을 오가며 예금·적금·대출 금리를 비교하는 게 번거로운 사람. 특히 전세자금대출·신용대출처럼 은행마다 조건 차이가 큰 상품을 알아보는 중이고, 안내만 받는 게 아니라 계좌 조회나 이체까지 AI가 대신 처리해주길 원하는 사용자.
- **② AI를 실제로 운영해야 하는 담당자** — 이런 AI 은행원을 은행·핀테크 서비스에 도입하려는 기획자·운영 담당자. 배포 후에도 답변 스타일을 실험(A/B 테스트)하거나 AI 모델을 바꿔가며 운영해야 하는 실무자에게 매치뱅크의 관리자 도구가 그대로 필요한 기능이 됩니다.

---

## 4. 핵심 가치 제안

- **진짜 업무를 수행하는 에이전트** — 안내로 끝나지 않고 계좌조회·상품추천·이체까지 직접 처리
- **실시간 데이터 기반 신뢰** — 금융감독원 공식 API에서 그때그때 가져온 실제 상품 정보로 안내(가짜/고정 데이터 아님)
- **안전을 고려한 설계** — 로그인 비밀번호와 분리된 이체 전용 비밀번호, 이상 행동 감지 기록
- **운영 가능한 AI** — 만들고 끝이 아니라, 배포 후에도 답변 품질을 실험하고 조정할 수 있는 관리자 도구 제공

## 5. 차별점

| 일반 은행 챗봇 | 매치뱅크 |
|---|---|
| 안내만 하고 실제 처리는 사람이 함 | AI가 계좌조회·상품비교·이체를 직접 수행 |
| AI가 원하면 바로 실행 | AI는 이체를 "제안"만 하고, 사람이 최종 확인 버튼을 눌러야 실행됨 — AI에게 무제한 실행 권한을 주지 않는 안전장치 |
| 정적/고정된 상품 목록 | 금융감독원 API로 실시간 조회한 5종 상품(예금·적금·주택담보대출·전세자금대출·신용대출) |

| 배포 후 손댈 방법이 없음 | 관리자가 답변 스타일을 실시간으로 비교(A/B 테스트)하고, AI 모델도 코드 수정 없이 바로 교체 가능 |
| 화면 조회 기록과 챗봇 대화 기록이 따로 놈 | 상품 페이지 조회 데이터와 AI 은행원 대화 중 검색 데이터를 하나로 합쳐, 은행별·카테고리별 실시간 인기 랭킹으로 제공 |

## 6. 주요 기능

**사용자 기능**
- **AI 은행원** — 대화로 계좌조회·상품추천·이체를 처리하는 AI 에이전트
- **내 계좌** — 잔액/거래내역 조회, 3단계(입력→확인→완료) 이체
- **상품안내** — 예금·적금·주택담보대출·전세자금대출·신용대출 실시간 비교. 상품 페이지 조회와 AI 은행원 검색 데이터를 합쳐 은행·카테고리별 실시간 인기 랭킹도 함께 제공
- **마이페이지** — 내 정보, 보안(이체 비밀번호 관리, 이상행동 기록 확인), 연결 계좌 관리, 즐겨찾기, 예약이체, 문의내역, 거래명세서
- **고객센터** — 공지사항, FAQ, 1:1 문의, 서식·약관 자료실

**운영자 기능 (백오피스)**
- 대시보드(전체 현황), 회원관리, 이체 모니터링, 이용통계
- **성능관리** — AI 모델/답변 스타일/시스템 프롬프트를 코드 수정 없이 바로 조정
- **프롬프트 A/B 테스트** — 답변 스타일별 실험 비교
- 금융상품 데이터 현황 관리, FAQ·공지사항 관리, 시스템 설정

## 8. 기술 스택 및 아키텍처

매치뱅크는 하나의 프로그램이 아니라 여러 개의 작은 서비스가 함께 동작하는 구조입니다. "직접 만든 부분"과 "외부에서 가져다 쓰는 부분"으로 나눠 정리하면 다음과 같습니다.

**① 자체 구축 시스템**
- **AI 은행원의 작동 구조(에이전트 로직)** — LangGraph라는 프레임워크로 만들었습니다. 사용자의 요청을 이해하고, 필요한 도구(계좌조회, 이체제안, 상품검색 등)를 스스로 골라 호출한 뒤 결과를 확인하고 다음 행동을 정하는 흐름을 매치뱅크가 직접 설계했습니다. 사람이 업무를 처리할 때 "확인하고 → 판단하고 → 실행하고 → 다시 확인하는" 과정과 비슷하게 동작한다고 이해하면 됩니다.
- **자체 웹 서버** — 계좌·이체·상품 정보를 관리하고 은행 업무를 실제로 처리하는, 매치뱅크가 직접 만든 서버입니다. FastAPI라는 프레임워크(서버를 만들 때 쓰는 도구)로 개발했습니다.
- **이체 처리 대기열(Kafka)** — 이체 요청이 몰려도 순서대로 안정적으로 처리되도록 대기열에 쌓아두고 별도 처리기가 순차적으로 실행합니다. 은행 창구에 번호표를 뽑고 순서대로 처리받는 것과 비슷한 구조입니다.
- **상품 검색/고객지원 검색(Elasticsearch 기반 RAG)** — 방대한 공지사항·FAQ·약관 중에서 질문과 가장 관련 있는 내용을 찾아 AI에게 참고자료로 제공합니다.
- **답변 재사용(Redis/ChromaDB 기반 시맨틱 캐시)** — 이미 비슷한 질문에 답한 적이 있다면 다시 계산하지 않고 재사용해, 더 빠르고 일관된 답변을 제공합니다.

**② 외부 연동 (가져다 쓰는 서비스·데이터)**
- **OpenAI의 AI 모델** — AI 은행원이 실제로 이해하고 판단하고 답변을 만들어내는 "두뇌" 자체는 매치뱅크가 만든 게 아니라 OpenAI가 제공하는 AI 모델입니다. 매치뱅크는 이 두뇌를 은행 업무에 맞게 활용하는 구조(위의 에이전트 로직)를 설계한 것이고, 두뇌 자체는 외부에서 빌려 쓰는 것입니다.
- **금융감독원 공식 데이터** — 정부기관이 이미 제공하는 데이터를 실시간으로 가져와, 예금·적금·대출 상품을 항상 최신 금리로 안내합니다.

(더 자세한 시스템 구성은 `architecture.mmd`, `시스템구성도.drawio`/`.pptx` 참고)

## 9. 성공지표 — 무엇을, 어떻게 측정했는가

매치뱅크는 실제 사용자가 없는 데모 프로젝트이기 때문에 "가입자 수"나 "만족도" 같은 사용자 지표는 존재하지 않습니다. 대신, **AI의 답변 품질을 스스로 검증할 수 있는 측정 체계를 직접 구축**하고 실제로 돌려본 결과를 성과로 삼았습니다.

- **답변 품질 자동 평가** — 1,000개의 질문·답변 세트를 만들어, AI(OpenAI)가 다른 AI의 답변을 채점하는 방식으로 자동 평가했습니다(20건씩 동시에 처리). 그 결과는 관리자 화면(백오피스 성능관리)에서 바로 확인할 수 있습니다. → 답변의 정확도와 일관성을 사람이 일일이 확인하지 않고도 검증할 수 있음을 보여줍니다.
- **캐시(답변 재사용) 효율 측정** — 같은 질문이 반복될 때 답변을 재사용한 비율을 추적 시스템(Phoenix)으로 실측했습니다. → 응답 속도와 비용 효율을 눈으로 확인 가능합니다.
- **프롬프트 A/B 테스트 실측 가능 구조** — 답변 스타일을 두 가지로 나눠 실시간으로 비교할 수 있는 기능을 실제로 구현·테스트했습니다. → 배포 후에도 서비스를 계속 개선할 수 있는 운영 체계를 갖췄음을 뜻합니다.

즉, 매치뱅크의 "성공"은 사용자 지표가 아니라 **품질을 스스로 확인하고 개선할 수 있는 구조를 만들었다는 것** 자체로 정의했습니다.

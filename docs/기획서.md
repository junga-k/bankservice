# 매치뱅크 (MatchBank)
### AI 뱅킹 에이전트 데모

작성자: junga-k
작성일: 2026-07-23
최종 수정: 2026-07-26 (리디자인·신규 기능 반영)

> 여러 은행을 오가며 상품을 비교하고, 안내만 해주는 챗봇에 답답함을 느낀 적 있다면 — 매치뱅크는 실제로 계좌를 조회하고, 상품을 비교하고, 이체까지 대신 처리해주는 AI 은행원입니다.

---

## 1. 프로젝트 개요 (한눈에)

매치뱅크는 은행 웹사이트에 "AI 은행원"을 심어, 사용자가 대화만으로 실제 은행 업무를 처리할 수 있게 만든 데모 서비스입니다. 단순히 질문에 답하는 챗봇이 아니라, 계좌 조회·상품 비교·이체 신청 같은 업무를 AI가 직접 수행하고, 그 결과를 사용자가 확인·승인하는 구조로 설계했습니다.

**핵심 하이라이트**
- 실제 업무를 수행하는 AI 에이전트 — 안내만 하는 게 아니라 계좌조회·이체·상품추천을 직접 실행
- 금융감독원(FSS) 공식 API로 실시간 상품 (5개) 비교 (예금·적금·주택담보대출·전세자금대출·신용대출)
- 이체는 AI가 "제안"만 하고, 최종 실행은 반드시 사용자 승인 — 안전장치 내장
- 운영자가 AI를 직접 튜닝·모니터링할 수 있는 관리자 도구(백오피스) 포함

---

## 2. 문제 정의 — 왜 만들었는가

시중의 은행 챗봇 대부분은 "자주 묻는 질문에 답하는 봇"에 머물러 있습니다. 계좌를 보려면, 상품을 비교하려면, 이체를 하려면 결국 사람이 직접 메뉴를 눌러가며 처리해야 합니다. 챗봇은 안내판일 뿐, 일을 대신해주지는 않습니다.

또한 대출·예금 상품을 비교하려면 은행마다 앱을 켜고 금리를 하나하나 확인해야 하는 번거로움이 있습니다. 특히 전세자금대출이나 신용대출처럼 은행별 금리 차이가 크고 조건이 복잡한 상품일수록 이 번거로움은 더 커집니다.

한 가지 문제가 더 있습니다. 대부분의 "AI 챗봇"는 만들고 나면 운영할 방법이 없습니다. 답변이 이상해도 무엇이 문제인지 확인할 방법이 없고, 프롬프트나 모델을 바꿔보고 싶어도 코드를 다시 배포해야 합니다.

매치뱅크는 이 세 가지 문제를 함께 풀기 위해 시작했습니다. 그래서 이름도 "AI 챗봇"이 아니라 **"AI 은행원"**입니다. 이 AI는 질문을 받으면 스스로 판단해서 필요한 도구(계좌 조회, 상품 검색, 이체 등)를 호출하고, 그 결과를 다시 확인한 뒤 다음 행동을 정하는 방식으로 동작합니다(기술적으로는 LangGraph라는 프레임워크의 "ReAct 에이전트" 구조를 사용합니다). 즉, "질문 하나에 대답 하나"로 끝나는 일반 챗봇과 달리, 목표를 달성할 때까지 스스로 여러 단계를 거쳐 일을 처리하는 것이 핵심 차이입니다.

## 3. 타겟 정의

문제 정의에서 바로 이어지는, 매치뱅크가 실제로 필요한 사람들입니다.

- **① 금융 상품을 비교해야 하는 소비자** — 여러 은행 앱을 오가며 예금·적금·대출 금리를 비교하는 게 번거로운 사람. 특히 전세자금대출·신용대출처럼 은행마다 조건 차이가 큰 상품을 알아보는 중이고, 안내만 받는 게 아니라 계좌 조회나 이체까지 AI가 대신 처리해주길 원하는 사용자.
- **② AI를 실제로 운영해야 하는 담당자** — 이런 AI 은행원을 은행·핀테크 서비스에 도입하려는 기획자·운영 담당자. 배포 후에도 프롬프트를 실험(A/B 테스트)하거나 AI 모델을 바꿔가며 운영해야 하는 실무자에게 매치뱅크의 관리자 도구가 그대로 필요한 기능이 됩니다.

---

## 4. 핵심 가치 제안

- **진짜 업무를 수행하는 에이전트** — 안내로 끝나지 않고 계좌조회·상품추천·이체까지 직접 처리
- **실시간 데이터 기반 신뢰** — 금융감독원 공식 API에서 그때그때 가져온 실제 상품 정보로 안내(가짜/고정 데이터 아님)
- **안전을 고려한 설계** — 로그인 비밀번호와 분리된 이체 전용 비밀번호, 이상 행동 감지 기록
- **운영 가능한 AI** — 만들고 끝이 아니라, 배포 후에도 답변 품질을 실험하고 조정할 수 있는 관리자 도구 제공

## 5. 차별점

| 일반 은행 챗봇 | 매치뱅크 |
|---|---|
| 안내만 하고 실제 처리는 사람이 함 | AI가 계좌조회·상품비교·이체를 직접 수행 |
| AI가 원하면 바로 실행 | AI는 이체를 "제안"만 하고, 사람이 최종 확인 버튼을 눌러야 실행됨 — AI에게 무제한 실행 권한을 주지 않는 안전장치 |
| 정적/고정된 상품 목록 | 금융감독원 API로 실시간 조회한 5종 상품(예금·적금·주택담보대출·전세자금대출·신용대출) |
| 로그인 비밀번호로 모든 걸 처리 | 이체 전용 6자리 비밀번호를 별도로 두어, 이체만큼은 한 단계 더 확인 |
| 예약 기능 없음 | 원하는 날짜에 이체가 실행되도록 예약/지연 이체 가능 |
| 배포 후 손댈 방법이 없음 | 관리자가 저장된 프롬프트와 지금 편집 중인 프롬프트를 실시간으로 비교(A/B)하고, 버전 이력으로 언제든 이전 설정으로 되돌릴 수 있음. AI 모델 교체도 코드 수정 없이 바로 가능 |

## 6. 주요 기능

**사용자 기능**
- **홈** — 공지사항·이벤트·특별상품과 실시간 연동되는 배너 캐러셀로 주요 소식 안내
- **AI 은행원** — 대화로 계좌조회·상품추천·이체를 처리하는 AI 에이전트, 답변에 좋아요/싫어요(이유 선택)로 피드백 가능
- **내 계좌** — 잔액/거래내역 조회, 3단계(입력→확인→완료) 이체
- **상품안내** — 예금·적금·주택담보대출·전세자금대출·신용대출 실시간 비교, 카테고리별 인기 상품 TOP5 통계, 은행 공식 사이트 바로가기, 관리자가 큐레이션한 특별상품(특판) 안내
- **마이페이지** — 내 정보, 보안(이체 비밀번호 관리, 이상행동 기록 확인), 연결 계좌 관리, 즐겨찾기, 예약이체, 문의내역, 거래명세서
- **고객센터** — 공지사항, FAQ, 이벤트(응모·추첨, 당첨자 발표), 1:1 문의, 서식·약관 자료실

**운영자 기능 (백오피스)**
- 대시보드(전체 현황), 회원관리, 이체 모니터링, 이용통계
- **성능관리** — 시스템 프롬프트·AI 모델을 코드 수정 없이 바로 조정, 인프라(Kafka·Elasticsearch·Phoenix 등) 연동 현황과 LLM·RAG 사용 지표 실시간 조회
- **프롬프트 관리** — 시스템 프롬프트 편집 + 버전 이력 조회/되돌리기 + 현재 저장된 프롬프트와 편집 중인 프롬프트의 실시간 A/B 비교, 사용자 답변 피드백(좋아요/싫어요) 집계
- 금융상품 데이터 현황 관리(FSS 실시간 상품 + 특별상품 큐레이션), FAQ·공지사항·이벤트 관리, 배너 관리(홈 화면 배너 이미지 업로드·연결 대상 설정)

## 8. 기술 스택 및 아키텍처

매치뱅크는 하나의 프로그램이 아니라 여러 개의 작은 서비스가 함께 동작하는 구조입니다. 각 부분이 맡은 역할만 정리하면 다음과 같습니다.

- **AI 은행원(에이전트)** — LangGraph라는 프레임워크로 만들었습니다. AI가 사용자의 요청을 이해하고, 필요한 도구(계좌조회, 이체제안, 상품검색 등)를 스스로 골라 호출한 뒤 결과를 확인하고 다음 행동을 정하는 구조입니다. 사람이 업무를 처리할 때 "확인하고 → 판단하고 → 실행하고 → 다시 확인하는" 과정과 비슷하게 동작한다고 이해하면 됩니다.
- **웹/앱 서버(FastAPI)** — 계좌·이체·상품 정보를 관리하고 은행 업무를 실제로 처리하는 서버입니다.
- **이체 처리 대기열(Kafka)** — 이체 요청이 몰려도 순서대로 안정적으로 처리되도록 대기열에 쌓아두고 별도 처리기가 순차적으로 실행합니다. 은행 창구에 번호표를 뽑고 순서대로 처리받는 것과 비슷한 구조입니다.
- **상품 검색/고객지원 검색(Elasticsearch 기반 RAG)** — 방대한 공지사항·FAQ·약관 중에서 질문과 가장 관련 있는 내용을 찾아 AI에게 참고자료로 제공합니다.
- **답변 재사용(Redis/VectorDB 기반 시맨틱 캐시)** — 이미 비슷한 질문에 답한 적이 있다면 다시 계산하지 않고 재사용해, 더 빠르고 일관된 답변을 제공합니다.
- **금융감독원 공식 API 연동** — 예금·적금·대출 상품 정보를 실시간으로 가져와 항상 최신 금리로 안내합니다.

(더 자세한 시스템 구성은 `architecture.mmd`, `시스템구성도.drawio`/`.pptx` 참고)

## 9. 성공지표 — 무엇을, 어떻게 측정했는가

매치뱅크는 실제 사용자가 없는 데모 프로젝트이기 때문에 "가입자 수"나 "만족도" 같은 사용자 지표는 존재하지 않습니다. 대신, **AI의 답변 품질을 스스로 검증할 수 있는 측정 체계를 직접 구축**하고 실제로 돌려본 결과를 성과로 삼았습니다.

- **답변 품질 자동 평가** — 10개 카테고리(상식·세계지리·수학·영어·문화예술·한국역사·논리·경제·파이썬코딩·과학) 999문항을 동시 실행해 응답 성공률·지연시간과 **정답 여부**까지 자동으로 측정하는 배치 도구(`batch_test.py`)를 만들었습니다. 채점은 수학처럼 정답이 결정적인 문항은 정답 문자열 비교로, 나머지는 AI가 다른 AI의 답변을 O/X로 채점하는 LLM-as-judge 방식으로 합니다. 결과는 관리자 화면(백오피스 성능관리)에서 바로 확인할 수 있습니다.
  - 최근 실행 결과(gpt-4o-mini, 999문항 171초): **응답 성공률 100%(999/999), 정확도 96.3%(950/987 채점), 평균 지연 1,038ms, 중앙값 863ms, p95 1,881ms.**
  - 카테고리별로는 수학·과학·영어·파이썬코딩이 100%, 경제 99.0%, 세계지리 97.0%, 한국역사 94.9%, 상식 93.9%, 문화예술 93.0%인 반면 **논리 추론은 84.5%로 뚜렷하게 낮았습니다** — 어떤 유형에서 약한지를 수치로 짚어낼 수 있다는 것이 이 측정 체계의 핵심입니다.
  - 문항이 은행 업무가 아니라 일반 지식인 이유는, 이 배치가 은행 도메인 정확도 평가가 아니라 **응답 파이프라인의 안정성과 지연 특성을 재기 위한 것**이기 때문입니다. 은행 업무 답변의 품질은 아래 사용자 피드백(좋아요/싫어요 + 사유) 집계로 따로 봅니다.
- **캐시(답변 재사용) 효율 측정** — 같은 질문이 반복될 때 답변을 재사용한 비율을, 추적 시스템(Phoenix)에 쌓인 최근 24시간 트레이스에서 실시간으로 집계해 관리자 화면에 표시합니다. → 응답 속도와 비용 효율을 눈으로 확인 가능합니다.
- **사용자 피드백 집계** — AI 답변마다 좋아요/싫어요를 남길 수 있고, 싫어요는 사유(부정확한 정보·원하는 답변이 아님·응답이 느림/오류·말투/스타일이 아쉬움·안전/법적 우려·기타)를 함께 받습니다. 관리자 화면에서 사유별 분포와 개별 문답을 확인할 수 있습니다. → 실제 대화에서 무엇이 문제였는지를 답변 단위로 추적할 수 있습니다.
- **프롬프트 A/B 테스트 실측 가능 구조** — 현재 저장된 프롬프트와 지금 편집 중인 프롬프트로 같은 질문에 대한 답변을 실시간으로 비교할 수 있는 기능을 실제로 구현·테스트했습니다. → 배포 후에도 서비스를 계속 개선할 수 있는 운영 체계를 갖췄음을 뜻합니다.

즉, 매치뱅크의 "성공"은 사용자 지표가 아니라 **품질을 스스로 확인하고 개선할 수 있는 구조를 만들었다는 것** 자체로 정의했습니다.
